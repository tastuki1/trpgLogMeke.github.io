## CoC 6版

BCDice の `Cthulhu` system。

主なコマンド:

- `CC<=n`
  `c=1`, `f=100` の D100 判定。
- `CCB<=n`
  `c=5`, `f=96` の D100 判定。
- `CBR(x,y)`
  組み合わせロール。`c=1`, `f=100`。
- `CBRB(x,y)`
  組み合わせロール。`c=5`, `f=96`。
- `RES(x-y)`
  抵抗表ロール。`c=1`, `f=100`。
- `RESB(x-y)`
  抵抗表ロール。`c=5`, `f=96`。
- `CC(x)<=n` / `CCB(x)<=n`
  `x` は故障ナンバー。出目が故障ナンバー以上なら故障判定を出す。

`CC` と `CCB` の違い:

- どちらも D100 判定。
- `CC` はクリティカル 1、ファンブル 100。
- `CCB` はクリティカル 1-5、ファンブル 96-100。
- `CC(x)` / `CCB(x)` の括弧は、CoC 6版では故障ナンバーを意味する。CoC 7版のボーナス・ペナルティダイスとは意味が違う。

`CBR` と `CBRB` の違い:

- どちらも組み合わせロール。
- `CBR(x,y)` は `CC` と同じく `c=1`, `f=100`。
- `CBRB(x,y)` は `CCB` と同じく `c=5`, `f=96`。

logmake 側の扱い:

- `CC` / `CCB` は技能名を取れる場合、成長判定対象にする。
- `CBR` / `CBRB` は tail の技能数と目標値数が一致する場合、技能ごとに成長判定対象にする。
- `RES` / `RESB` は技能名を取れないため、本文ハイライト対象にはできるが成長判定には入れない。
- 故障単独は `故障` ラベル、`ファンブル＆故障` は `ファンブル` ラベルにする。

## CoC 7版

BCDice の `Cthulhu7th` system。

主なコマンド:

- `CC(x)<=n`
  `x` はボーナス・ペナルティダイス。省略可。
- `CC(x)<=n r/h/e/c`
  難易度指定。`r`, `h`, `e`, `c` を使う。
- `CBR(x,y)`
  組み合わせ判定。
- `FAR(w,x,y,z,d,v)`
  自動火器の射撃判定。

CoC 7版の `CC`:

- `CC`, `CC1`, `CC+1`, `CC(1)` などは、ボーナス・ペナルティダイスの個数を表す。
- 正の値はボーナスダイス、負の値はペナルティダイス。
- ボーナス・ペナルティダイスは 1D100 の 10 の位を選び直しうるもの。BCDice 出力の最後の数値が採用後の出目。
- CoC 6版の `CC(x)` / `CCB(x)` は故障ナンバーだが、CoC 7版の `CC(x)` はボーナス・ペナルティダイスなので混同しない。

難易度 suffix:

- `r`: レギュラー
- `h`: ハード
- `e`: イクストリーム
- `c`: クリティカル
- `CC<=70h` や `CC<=70e` は、BCDice の出力文が単に `成功` になる場合がある。
- logmake の成長判定では、結果文だけでなくコマンド suffix も見て `ハード` / `イクストリーム` を分類する。

例:

```txt
CC<=70r (1D100<=70) ボーナス・ペナルティダイス[0] ＞ 81 ＞ 81 ＞ 失敗
CC+3<=70e (1D100<=14) ボーナス・ペナルティダイス[3] ＞ 63, 73, 33, 13 ＞ 13 ＞ 成功
CC-3<=70h (1D100<=35) ボーナス・ペナルティダイス[-3] ＞ 62, 52, 52, 12 ＞ 62 ＞ 失敗
CC(3)<=70h (1D100<=35) ボーナス・ペナルティダイス[3] ＞ 13, 13, 3, 33 ＞ 3 ＞ 成功
CC(-3)<=70e (1D100<=14) ボーナス・ペナルティダイス[-3] ＞ 53, 63, 33, 63 ＞ 63 ＞ 失敗
```

logmake 側の扱い:

- 現状は `CC` と `CBR` を解析対象にする。
- `FAR` は今後 fixture を追加してから対応する。
- CoC 7版に `CCB`, `CBRB`, `RES`, `RESB` はないものとして扱う。

## エモクロア

BCDice の `Emoklore` system。

主なコマンド:

- `xDM<=y`
  技能値判定。個数省略時は 1 個。
- `sDAa+z`
  技能レベル、能力値、ダイスボーナスから判定する。
- クリティカル値は `1`、ファンブル値は `10`。

logmake 側の今後の扱い:

- CoC の成長判定に直接混ぜず、汎用的な `DiceEvent` と system 別 analyzer を分ける。
- エモクロア対応時は `DM` / `DA` 用 fixture を追加してから実装する。

## 実装メモ

- CCFOLIA の通常判定は、基本的に 1 `<p>` ブロックにつき 1 判定として fixture を作る。
- `x3`, `rep2`, `repeat2` などの繰り返しコマンドだけは、1 ブロック内に複数結果を持つ。
- 繰り返しコマンドでは `#1` がコマンド行と同じ行にある場合と、次行にある場合の両方を許容する。
- 初期値成功は、初期値 JSON 自体を `{ 技能名: 初期値 }` の辞書として保持し、技能名と判定値のペアが一致する場合だけ判定する。
- CoC 6版/7版のコマンド解析、option 抽出、技能名の正規化、成長判定分類は system adapter の `log.parseToken()` と `growth` で切り替える。
